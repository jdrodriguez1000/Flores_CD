# CC-004: Corrección de Vacíos y Ambigüedades en BDD Contract

**Fecha:** 2026-04-29
**Agente Responsable:** ai-business-strategist
**Documentos Afectados:** `docs/governance/behavior.md` (v1.3.0 -> v1.4.0)

## Cambio
Se aplicaron 5 subsanaciones críticas sobre el Contrato de Comportamiento (`behavior.md`) detectadas tras una auditoría "Devil's Advocate":
1. **US-01 y US-03**: Inclusión de aserciones explícitas para poblar la columna `especie_confirmada` en los estados terminales (`confirmada_a1`, `confirmada`, `corregida`).
2. **RF-08**: Corrección de la aserción de persistencia del modelo tratamiento para usar `estado = 'shadow'` en lugar del flag `is_shadow = True`, garantizando alineación con el esquema SQLite (Decisión D-023).
3. **US-03**: Inclusión de aserción para registrar obligatoriamente la identidad del revisor en `analista_confirmador_id`.
4. **RF-01b**: Conversión del escenario en un "Esquema del Escenario" parametrizado (Scenario Outline) para forzar pruebas automáticas de los bordes fuera de umbral sobre las 4 variables predictoras.
5. **RF-08**: Inclusión de un paso de garantía de "Mutabilidad Cero" (`Y los campos de interacción humana del registro shadow deben permanecer nulos permanentemente...`) para evitar fugas de datos operativos hacia los registros sombra por mala manipulación de ORM.

## Justificación
El Contrato BDD (v1.3.0) presentaba deficiencias técnicas que, si se trasladaban a los test automatizados, generarían un sistema incapaz de medir correctamente el KPI-T-05 (por faltar el `especie_confirmada`), sin trazabilidad del revisor (por faltar el `analista_confirmador_id`), y propenso a contaminación de registros de Shadow Testing (por carecer del candado de mutabilidad cero). Además, el error en la aserción del estado `shadow` entraba en colisión directa con el diccionario de datos del BRD. La paramatrización de RF-01b blinda el frontend ante la ingesta de ruido que degrada el modelo.

## Impacto
* **`docs/governance/behavior.md`**: Actualizado a la versión 1.4.0. Se modificaron los pasos `Entonces` de los escenarios afectados y se amplió la Matriz de DoD.
* **`docs/references/decisions.md`**: Se registran las micro-decisiones de cierre de BDD bajo el ID CC-004.
