## CC-ID: CC-001

## Cambio

Agregar el campo `analista_id` (texto libre, sin autenticacion) como identificador minimo de trazabilidad en el flujo de prediccion y confirmacion del dashboard.

## Justificacion

El BRD v1.0.0 declaraba simultaneamente:
- RF-04/RF-05: flujo que requiere distinguir al analista generador del analista confirmador.
- Seccion 11.2: exclusion explicita de autenticacion de usuarios.

Esta contradiccion implicaba que el mismo analista podia confirmar su propia prediccion pendiente, anulando el control operativo del flujo de baja confianza. La solucion minima es un campo de texto libre `analista_id` que el analista ingresa al iniciar el dashboard, sin validacion de identidad, suficiente para bloquear la auto-confirmacion.

## Impacto

| Documento | Seccion afectada | Cambio aplicado |

| `docs/governance/BRD.md` | RF-01 | Renombrado a RF-01a/RF-01b. Agregado `analista_id` como campo obligatorio al iniciar el dashboard. |
| `docs/governance/BRD.md` | RF-04 | Prediccion `pendiente` registra el `analista_id` generador. Agrega restriccion de auto-confirmacion. |
