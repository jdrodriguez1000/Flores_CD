# CC-006: Refinamiento Operativo y Calidad de Ground Truth

**ID:** CC-006
**Fecha:** 2026-04-29
**Estado:** Aprobado

## Cambio
1. Añadir el estado "Anulada" para el Analista 2 (exclusión de casos anómalos o basura).
2. Definir que el UI debe bloquear temporalmente los botones tras el envío (Doble Submit).
3. Especificar que la escritura a DB debe ser un bloque transaccional atómico (ROLLBACK en caso de fallo del Modelo Control).
4. Definir valores de borde exactos en ejemplos de validación de rangos.
5. Aclarar el cálculo de éxito (True Positive) cuando Analista 2 "Corrige" eligiendo la especie predicha originalmente por el modelo.

## Justificación
Prevenir registros duplicados, evitar la contaminación del Gold dataset con datos basura obligados a ser clasificados, resolver ambigüedades en test de valores límite, prevenir registros shadow huérfanos y asegurar que la métrica de éxito del modelo sea justa y precisa respecto al ground truth (`especie_confirmada`).
